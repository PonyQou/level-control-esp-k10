## 1. 实验目的

在行空板 K10（ESP32-S3）上实现液位容器仿真、PID 闭环控制、LCD 图形化显示与
Modbus TCP 从站通信，并在 PC 上实现 Modbus TCP 主站上位机，完成实验数据的
采集、记录与曲线分析。

## 2. 软件系统架构

```
┌──────────────── K10 固件（ESP-IDF v6.1, C） ────────────────┐
│  控制任务(20ms, 核0)    传感器任务(1s)    Modbus 事件任务      │
│   ├ 按键消抖/出水阀调节   ├ AHT20 温度     ├ 写参数校验/拒绝    │
│   ├ PID(按周期)          └─────────────── ├ NVS 保存/恢复      │
│   └ 液位模型 tank_step                     └───────────────────│
│        │ 锁内刷新输入寄存器（esp-modbus v2 从站任务自建轮询）     │
│  XL9535(背光+按键A/B) ─ I2C(47/48) ─ AHT20(@0x38)             │
│  LCD ILI9341(SPI: 12/21/14/13) ─ LVGL 9.5 ─ esp_lvgl_port    │
│  WiFi STA（断线自动重连，不销毁 netif）                         │
└───────────────────────────┬──────────────────────────────────┘
                            │ Modbus TCP :502 站号1
┌──────────────── PC 上位机（Python 3.13） ────────────────────┐
│  tkinter GUI(主线程) ◄─queue─► 轮询工作线程(独占ModbusTcpClient)│
│  状态灯/数值/参数写入/错误提示    读输入寄存器→CSV(utf-8-sig)     │
│  matplotlib 实时曲线/CSV回放/PNG   写命令:SP/Kp/Ki/Kd/阀开度等  │
└──────────────────────────────────────────────────────────────┘
```

**设计要点**
- 任务划分：控制 20ms / 传感器 1s / Modbus 事件 / LVGL / WiFi 事件，互不阻塞；
  断网时从站监听 socket 常驻，本地模型与 PID 完全不受影响
- 寄存器表：保持寄存器 26 个（参数）+ 输入寄存器 24 个（状态），float32 占 2
  寄存器统一 ABCD 布局；非法地址由协议栈回 0x02，参数越界由固件校验恢复原值
- 线程安全：上位机 ModbusTcpClient 非线程安全 → 单工作线程 + 双队列 + after()
- PID：位置式 + 条件积分抗饱和 + 微分先行（设定值阶跃无冲击）

## 4. 大模型辅助开发过程（重点章节）

本项目的开发全程使用 Claude Code 辅助，以下是关键节点与解决的问题。

### 4.1 调研阶段：多代理并行调研 + 原理图解析

- 4 路并行调研（IDF v6.1 发布状态与安装方式 / K10 硬件与引脚 / esp-modbus v2
  API / pymodbus 3.x API），交叉验证出关键事实：
  - **ESP-IDF v6.1 于 2026-08-27 发布**，旧安装器不支持 6.x，必须用 EIM 或源码包
  - **K10 按键不在 ESP32 GPIO 上**：A/B 键经 I2C 扩展芯片 XL9535(0x20) 的
    P05/P11 读取，背光也在 XL9535(P00)——这是官方原理图解析 + BSP 源码核对得出，
    若按「按键直连 GPIO」的常规思路写会白费一版代码
  - **esp-modbus 在 IDF v6 只有 v2 句柄式 API**（网上 v1 教程全部失效）

### 4.2 仿真先行：抓出模型级 bug（详见 docs/PID调参记录.md）

- 将固件 tank_model.c/pid.c **逐行移植**到 Python 做闭环仿真，发现液位公式
  多乘 1000（单位换算 L→m³ 与 m→mm 系数抵消），液位 1000 倍速振荡永不收敛。
  修正后 5 个工况全部收敛，稳态误差≈0，提前满足 ±2mm 验收
- Ki 扫描确定默认参数 Kp=3/Ki=0.05/Kd=0.5：零超调，收敛时间受物理灌水速度限制

### 4.3 上位机先行 + 模拟从站联调

- 硬件未到场时先写完 PC 主站，并用 pymodbus 3.16 新 API（SimData/SimDevice +
  action 回调）自建模拟从站做端到端测试，把库的版本坑提前排掉：
  - `ModbusSlaveContext` 弃用改名 `ModbusDeviceContext`
  - 动态数据必须经 async action 回调写入运行时寄存器（SimCore 启动时冻结拷贝）
  - 运行时寄存器末尾有哨兵元素，切片赋值需留长度
  - matplotlib 嵌入 tkinter 时需先 `root.quit()` 再 `destroy()` 才能退出事件循环
