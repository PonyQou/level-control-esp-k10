基于嵌入式系统的液位控制站 —— 实验报告（草稿）

状态：完整版（2026-11-13）。全部章节有真实实验数据支撑。 交付前转 PDF（VSCode Markdown PDF 插件或 Typora）。

1. 实验目的

在行空板 K10（ESP32-S3）上实现液位容器仿真、PID 闭环控制、LCD 图形化显示与 Modbus TCP 从站通信，并在 PC 上实现 Modbus TCP 主站上位机，完成实验数据的 采集、记录与曲线分析。

2. 软件系统架构

┌──────────────── K10 固件（ESP-IDF v6.1, C） ────────────────┐
│  控制任务(20ms, 核0)    传感器任务(1s)    Modbus 事件任务      │
│   ├ 按键消抖/出水阀调节   ├ AHT20 温度     ├ 写参数校验/拒绝    │
│   ├ PID(按周期)          └─────────────── ├ NVS 保存/恢复      │
│   └ 液位模型 tank_step                     └───────────────────│
│        │ 锁内刷新输入寄存器（esp-modbus v2 从站任务自建轮询）     │
│  XL9535(背光+按键A/B) ─ I2C(47/48) ─ AHT20(@0x38)             │
│  LCD ILI9341(SPI: 12/21/14/13) ─ LVGL 9.5 ─ esp_lvgl_port    │
│  WiFi STA（断线自动重连，不销毁 netif）                         │
└───────────────────────────┬──────────────────────────────────┘
                            │ Modbus TCP :502 站号1
┌──────────────── PC 上位机（Python 3.13） ────────────────────┐
│  tkinter GUI(主线程) ◄─queue─► 轮询工作线程(独占ModbusTcpClient)│
│  状态灯/数值/参数写入/错误提示    读输入寄存器→CSV(utf-8-sig)     │
│  matplotlib 实时曲线/CSV回放/PNG   写命令:SP/Kp/Ki/Kd/阀开度等  │
└──────────────────────────────────────────────────────────────┘

设计要点 - 任务划分：控制 20ms / 传感器 1s / Modbus 事件 / LVGL / WiFi 事件，互不阻塞； 断网时从站监听 socket 常驻，本地模型与 PID 完全不受影响 - 寄存器表：保持寄存器 26 个（参数）+ 输入寄存器 24 个（状态），float32 占 2 寄存器统一 ABCD 布局；非法地址由协议栈回 0x02，参数越界由固件校验恢复原值 - 线程安全：上位机 ModbusTcpClient 非线程安全 → 单工作线程 + 双队列 + after() - PID：位置式 + 条件积分抗饱和 + 微分先行（设定值阶跃无冲击）

4. 大模型辅助开发过程（重点章节）

本项目的开发全程使用 Claude Code 辅助，以下是关键节点与解决的问题。

4.1 调研阶段：多代理并行调研 + 原理图解析

  • 4 路并行调研（IDF v6.1 发布状态与安装方式 / K10 硬件与引脚 / esp-modbus v2 API / pymodbus 3.x API），交叉验证出关键事实：
  • ESP-IDF v6.1 于 2026-08-27 发布，旧安装器不支持 6.x，必须用 EIM 或源码包
  • K10 按键不在 ESP32 GPIO 上：A/B 键经 I2C 扩展芯片 XL9535(0x20) 的 P05/P11 读取，背光也在 XL9535(P00)——这是官方原理图解析 + BSP 源码核对得出， 若按「按键直连 GPIO」的常规思路写会白费一版代码
  • esp-modbus 在 IDF v6 只有 v2 句柄式 API（网上 v1 教程全部失效）

4.2 仿真先行：抓出模型级 bug（详见 docs/PID调参记录.md）

  • 将固件 tank_model.c/pid.c 逐行移植到 Python 做闭环仿真，发现液位公式 多乘 1000（单位换算 L→m³ 与 m→mm 系数抵消），液位 1000 倍速振荡永不收敛。 修正后 5 个工况全部收敛，稳态误差≈0，提前满足 ±2mm 验收
  • Ki 扫描确定默认参数 Kp=3/Ki=0.05/Kd=0.5：零超调，收敛时间受物理灌水速度限制

4.3 上位机先行 + 模拟从站联调

  • 硬件未到场时先写完 PC 主站，并用 pymodbus 3.16 新 API（SimData/SimDevice + action 回调）自建模拟从站做端到端测试，把库的版本坑提前排掉：
  • ModbusSlaveContext 弃用改名 ModbusDeviceContext
  • 动态数据必须经 async action 回调写入运行时寄存器（SimCore 启动时冻结拷贝）
  • 运行时寄存器末尾有哨兵元素，切片赋值需留长度
  • matplotlib 嵌入 tkinter 时需先 root.quit() 再 destroy() 才能退出事件循环

4.4 环境安装攻坚（本次项目最大的坑）

ESP-IDF v6.1 环境安装共攻克 8 个连环问题，记录排查方法：

# 问题 现象 定位方法 解决
1 gitee 克隆卡死 git 进程无网络活动、磁盘 40 分钟零增长 进程网络连接 + 磁盘增量监测 改 CDN 直下 v6.1 源码 zip（1.95GB 含子模块）
2 批处理中文注释 '链安装脚本' 不是命令 错误指向注释行内容 批处理改纯 ASCII
3 MSYSTEM 环境变量 install.bat 拒绝运行 读 install.bat 源码发现 MSYSTEM 检测 cmd 中 set MSYSTEM=
4 cmd 不解析无路径 bat 'install.bat 不是命令'（文件明明存在） 二分测试定位到调用方式 加 .\ 前缀
5 MSYS 路径转换 nul 重定向报"找不到路径" 单条命令隔离测试 去掉 > nul 重定向
6 中文路径 cmake 崩溃 exit 0xC0000409 出树构建对比实验 固件工程移纯英文路径 D:\esp\projects
7 ccache 编码异常 filesystem error: Illegal byte sequence 编译日志定位组件 禁用 ccache（英文路径后恢复）
8 Kconfig 配置不生效 LVGL 浮点格式化开关无效（界面全是 f 占位符） 发现 LV_CONF_SKIP=y 跳过配置 直接写 sdkconfig

方法论：每次只改一个变量 → 最小化复现 → 读工具源码找检测逻辑 → 绕过而非硬改。

4.5 代码审查：独立代理对照 IDF 头文件逐项核查

派独立审查代理对照磁盘上的 IDF v6.1 头文件逐项核对 API，发现并修复：

  • W2 严重：参数校验缺 isfinite()——NaN 与任何数比较均为 false，可绕过范围校验毒化模型
  • I1：积分清零命令未实现（上位机按钮失灵）
  • I3：开机 5 秒内"主站已连"误报（时间戳初值问题）
  • W4：int64 时间戳在 Xtensa 上读写撕裂 → 改 uint32
  • I5：停止状态显示陈旧流量/PID 值
  • E1：ILI9341 驱动在 IDF v6.1 已移出为托管组件 esp_lcd_ili9341
  • 验收实验追加发现：esp-modbus v2 的 mb_param_info_t.size 单位是寄存器个数（非字节），初版 >>1 导致单寄存器参数（PID 周期）绕过全部校验——双寄存器 float32 碰巧不受影响而掩盖了该 bug，由越界测试暴露

另：真机实测纠正原理图推断——按键 A/B 实际在 XL9535 P02/P14（原理图网络名 P5/P11 是 micro:bit 边缘连接器引脚名），通过"按下按键观察输入寄存器位跳变"的实测方法确认。

5. 实验结果

5.1 液位模型与 PID 控制（真机实测，2026-11-13）

实验 稳态误差 首次进入 ±2mm 备注
A 稳态基线（SP=250） 平均 -0.04mm， max 0.04mm
B 设定阶跃 250→350 末段平均 -0.32mm 18s 超调仅 1.6mm
C 出水阀扰动 30→60% 末段平均 +0.42mm 快速恢复 液位仅跌落 3.4mm 即被 PID 拉回
D 越界写入拒绝 SP=99999 / 阀150% / 面积0 / PID周期1ms 全部拒绝 ✓ 见 4.5 节的 bug 修复记录

曲线图：pc_master/实验数据/曲线/{A_稳态,B_阶跃,C_扰动}.png

验收实验揪出的真 bug（4.5 节补充）：esp-modbus v2 的 mb_param_info_t.size 单位是寄存器个数（头文件注释为 number of registers），初版代码误当作字节 做了 >>1，导致单寄存器参数（PID 周期）的写入绕过全部校验被直接接受。 双寄存器 float32 参数碰巧不受影响，掩盖了该 bug。修复：n = info->size。

5.2 LCD 显示

  • 全界面统一 20px 字体 + 颜色分层（标题白/标签浅灰/数值荧光青）+ 圆角容器式储液罐 （液面随罐形裁剪）+ 圆角卡片边框 + 状态灯（主站 绿/红、已到位 绿/琥珀）
  • 布局经 PC 模拟器程序化验证（对象树几何断言 + framebuffer 像素断言 40+ 项全绿）： 无越界、无重叠、同列对齐、文本完整、颜色正确
  • 显示信息齐全：标题/IP/设定/实际/IN/OUT 阀位与流量/液温/主站/已到位/按键提示

5.3 Modbus TCP 通信

  • 读写：PC 主站读 24 输入寄存器 + 26 保持寄存器 @500ms 稳定无丢帧；写 SP/阀门/PID 参数即时生效
  • 越界拒绝：SP=99999 / 阀=150% / 面积=0 / PID周期=1ms 全部拒绝并保持原值
  • 断网自持：热点关闭期间设备连续运行（串口记录 5 次自动重连尝试），恢复后自动重连， 主站无需干预即可恢复轮询
  • 主站连接指示：持续轮询 1s 内状态位置位（实测 t+0→False, t+1→True）

5.4 按键操作

  • A/B 键 ±10% 调整出水阀开度（0~100% 封顶），消抖 3 采样 + 按住不重复 + 上电假按键防护
  • 真机实测日志：B 键 30→20%，A 键 20→30%，响应可靠

6. 结论

项目一全部验收标准达成，关键数据：稳态误差 ±0.04mm（要求 ±2mm）、设定阶跃 18s 进入 ±2mm、扰动 3.4mm 跌落即被拉回、断网自动重连、越界写入 100% 拒绝。

工程方法上最有价值的三个实践： 1. 仿真先行：模型/PID 在烧录前经 Python 逐行移植仿真验证，提前发现单位换算 bug 2. 程序化 UI 验证：无视觉能力下的界面开发闭环——PC 模拟器 + 对象树几何断言 + 像素断言，40+ 项断言全绿后才上真机 3. 独立代码审查：对照 IDF 头文件的逐项 API 核查 + 验收实验兜底， 两轮各抓出一个真实 bug
