# PID 调参记录（仿真验证，2026-11-11）

> 方法：把固件 `tank_model.c` / `pid.c` 的 C 代码**逐行移植**到 Python 做闭环仿真，
> 在硬件烧录前验证控制算法。这是"大模型辅助开发"的典型环节——先用仿真排除模型级错误，
> 再上真机调传感器级问题。

## 发现并修复的关键 bug：液位公式多了 ×1000

初版 `tank_model.c` 的液位公式写为
`dh = (Qin−Qout)/60/A × 1000 × dt`，仿真立刻暴露异常：液位以真实 1000 倍
速度在空罐/满罐间疯狂振荡（1 秒内 334mm→500mm），PID 输出在 0%/100% 之间
打满形成极限环，永远无法稳定。

单位推导：Q[L/min]÷60 → L/s → ×0.001 L→m³ → ÷A[m²] → m/s → ×1000 m→mm。
**L→m³ 的 0.001 与 m→mm 的 1000 恰好抵消**，正确公式为：

```
dh[mm] = (Qin − Qout) / 60 / A[m²] × dt[s] × speed
```

修正后仿真全部收敛。**这个 bug 如果不先在仿真里暴露，真机联调时会被误判成
PID 参数问题，浪费大量时间**——这正是先仿真的价值。

## 修正后的仿真结果（默认参数 Kp=3, Ki=0.05, Kd=0.5, PID周期=200ms）

| 场景 | 首次进入 ±2mm | 末尾稳态误差 | 结论 |
|---|---|---|---|
| 标称 SP=250 出水阀30% | 50s | 0.00mm | ✅ |
| 设定值阶跃 250→350 @600s | 50s | 0.00mm | ✅ |
| 扰动：出水阀 30→60% @600s | 50s | 0.00mm | ✅ 自动恢复 |
| 极端：SP=400 出水阀70% | 141s | 0.00mm | ✅ |
| SP=300 出水阀50% | 73s | 0.00mm | ✅ |

**稳态误差均为 0（积分作用），远优于验收标准 ±2mm。**

## 参数敏感性分析

扫描 Ki = 0.05/0.1/0.15/0.2/0.3（Kp=3, Kd=0.5）：

| Ki | 首次±2mm | 最大超调 |
|---|---|---|
| 0.05 | 50s | 0.2mm ✅ |
| 0.1 | 46s | 2.2mm |
| 0.15 | 44s | 3.7mm |
| 0.2 | 43s | 4.9mm |
| 0.3 | 42s | 6.7mm |

**收敛时间主要由物理灌水速度决定**：0→250mm 满阀（8 L/min，A=200cm²）灌水
本身就需 ~38s，加大 Ki 只能把 50s 压到 42s，却引入超调。故默认参数取
**Kp=3, Ki=0.05, Kd=0.5**：零超调、50s 达标。Kd 对慢过程几乎无作用
（微分先行抑制设定值阶跃冲击）。

演示时如需更快，可通过 Modbus 调大"仿真速度"（0.1~10 倍）或换小容器面积，
不需要动 PID 参数。

## 对固件的修改

1. `tank_model.c`：液位公式去掉 ×1000（并注释推导过程）
2. `pc_master/mock_slave.py`：模型公式同步修正（与固件严格一致）
3. PID 实现要点：位置式 + 输出限幅 0~100% + **条件积分抗饱和**（输出饱和且
   误差方向不利于退出时不积分）+ **微分先行**（对测量值微分，设定值阶跃无冲击）
