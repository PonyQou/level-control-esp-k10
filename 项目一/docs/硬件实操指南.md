# 硬件实操指南（M0 → M6 验证流程）

> 分工：**所有命令行操作由 AI 在电脑上执行**（编译/烧录/监视日志），
> 你只需要做「物理操作」：插线、按按钮、提供 WiFi 信息、观察现象。
> 每个阶段有明确的「看到什么算通过」。
> 固件工程在 `D:\esp\projects\k10_level_control\firmware`（纯英文路径，
> 中文路径会令 ESP-IDF 工具链崩溃）。

## 阶段 0：硬件连接（1 分钟）

1. 拿 USB-C 数据线（**要数据线**，不是纯充电线）一端插 K10 的 USB-C 口
2. 另一端插电脑 USB 口
3. 看 K10 屏幕是否亮起（出厂程序会显示内容——这同时验证了背光和屏幕）
4. 告诉我「已插线」，我来探测串口

> K10 用原生 USB（USB-Serial-JTAG），Windows 会自动装驱动，不需要外接串口转接器。

## 阶段 1：首次烧录 M0 自检

我执行 `idf.py flash`，你需要：
- 若烧录报「无法进入下载模式」：**按住 BOOT 键不放 → 点一下 RST → 松开 BOOT**，再告诉我重试
- 成功后我会打开日志监视，**通过标准**：看到
  ```
  Flash: 16 MB (应为 16)
  PSRAM: 8 MB (应为 8)
  ```
  说明 Flash/PSRAM 配置正确（这是 K10 特有配置，错了后面全错）

## 阶段 2：外设自检（XL9535 + AHT20）

烧录后看日志，**通过标准**：
- `XL9535 初始化完成（背光已点亮）` + **屏幕背光亮**
- `AHT20 初始化完成`
- **按下 K10 的 A 键** → 日志出现 `A 键：出水阀开度 xx%`（xx 每次 +10，到 100 封顶）
- **按下 B 键** → 同理 −10%
- 液位模型每秒打印：液位应从 0 持续上升（罐子在被 PID「灌水」）

## 阶段 3：WiFi + Modbus TCP 联调（需要你提供 WiFi）

1. 告诉我 WiFi 名称和密码（我写进本机配置，**不会**出现在提交的源码 zip 里）
2. 重新编译烧录，日志出现 `已连接: 192.168.x.x` 后，**把日志里的 IP 告诉我**
3. 我在电脑上跑上位机（`python main.py`）连这个 IP，**通过标准**：
   - 上位机「主站已连」黄灯亮、数值实时刷新
   - 上位机把设定液位改成 300 → K10 日志无报错、液位向 300 收敛
   - 上位机写入越界参数（如设定液位 99999）→ 提示被拒绝
   - 上位机点「开始记录」→ 产生 CSV 文件

## 阶段 4：断网自持测试（验收项）

- 关掉路由器/拔掉电脑 WiFi 热点 → **K10 屏幕显示不变、模型继续运行**
- 恢复网络 → 上位机自动重连，无需任何操作

## 阶段 5：启用 LCD 界面

我改配置重新编译后，**通过标准**（对照老师示例界面）：
- 屏幕显示：标题「液位控制站」、IP、罐体+液面动画、设定/实际值、IN/OUT 阀位与流量、液温、状态灯（主站黄/已到位青绿）、底部「出水阀 A+10% B-10%」
- 若方向颠倒/颜色错乱（红蓝互换、镜像），告诉我现象，我只调显示配置不改布局

## 阶段 6：验收录制（最后）

1. 稳态演示：设定 250mm，等「已到位」灯亮，稳定 ≥1 分钟（记录稳态误差 ≤±2mm）
2. 扰动演示：按 A 键出水阀 +30%，观察液位下降后 PID 自动恢复
3. 上位机录屏：改设定值、改 PID 参数、CSV 记录与曲线回放
4. 我配合你用手机/录屏软件录 3 分钟内视频

## 常见问题预案

| 现象 | 处理 |
|---|---|
| 烧录找不到板子 | 按住 BOOT 点 RST 进入下载模式；换 USB 口/线 |
| 日志乱码 | 监视器波特率问题，告诉我即可 |
| 背光不亮 | XL9535 I2C 问题，我查日志定位 |
| 连不上 WiFi | 确认 2.4GHz（K10 不支持 5GHz WiFi）、密码无误 |
| 上位机连不上 | 核对 IP 与电脑是否同一网段；AP 隔离（校园网/访客网络常见）需换手机热点 |
