# UI 开发协作工作流 v2（无需视觉能力的验证闭环）

## 修正声明

第一版方案假设 agent 能直接读图——**不成立**（当前模型无视觉能力）。
v2 的核心转变：**界面验证从"看"变成"算"**——布局、对齐、重叠、层级这些
视觉问题全部可以转化为几何断言和像素断言，用代码验证，比人眼更严格。

## 盲改循环的病根（不变）

人看屏幕 → 视觉 agent 转述 → 文本描述 → 我猜测 → 改错。
任何经过文字转述的视觉反馈都有信息损耗和 OCR 噪声。

## 方案 B+：LVGL PC 模拟器 + 程序化验证（主线，无需视觉）

LVGL 官方 PC 模拟器（lv_port_pc / SDL2）运行 ui.c 的界面代码，
窗口即屏幕。在此基础上加两层**代码验证**，完全替代人眼：

### 第 1 层：几何断言（widget 树自检）
模拟器里遍历 LVGL 对象树，输出每个控件的坐标/尺寸/文本/字体/颜色，
用断言脚本核对：
- 无重叠：标题区与状态行矩形不相交、分隔线与任何控件不相交
- 同列对齐：设定/实际/IN/OUT/液温 的 x 坐标一致
- 不越界：所有控件在 240×320 内且离边 ≥ 4px
- 层级正确：重点数据的字号/颜色配置符合规范

### 第 2 层：像素断言（framebuffer 采样）
模拟器截取 framebuffer，用代码采样像素：
- 背景色、液位填充色、状态灯亮/灭颜色符合设计值
- 液位动画：fill 区域顶部 y 随 level 变化
- 文字渲染非空（文本区域存在非背景像素，即字体真正渲染了字符）

```
改 ui.c → PC 编译 → 跑模拟器 → 跑断言脚本 → 失败即修
（全自动、几分钟一轮、零人工、零烧录）
```

### 真机差异只剩一件事
模拟器无法验证的：面板 BGR 字节序 / 镜像 / 亮度。
用**验收画面**（四边标签+纯色块）烧录一次，请你的视觉 agent 看一张照片
做一次性核对即可——这是唯一需要"眼睛"的环节，且只需要一次。

## 方案 A'：真机照片（仅作最终验收，不参与迭代）
- 照片 → 你的视觉 agent 描述 → 我对照"验收画面清单"逐项打勾
- 不用于布局迭代（迭代全在模拟器完成）

## 分工总结

| 环节 | 谁做 | 工具 |
|---|---|---|
| 布局迭代 | 我（全自动） | PC 模拟器 + 几何/像素断言 |
| 显示配置验收 | 你的视觉 agent | 验收画面照片一次 |
| 功能验收 | 我 | Modbus 数据 + 串口日志 |
